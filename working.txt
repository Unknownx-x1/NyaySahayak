================================================================================
NYAYSAHAYAK: MULTI-AGENT LEGAL AI SYSTEM ARCHITECTURE & WORKING SPECIFICATION
================================================================================

1. SYSTEM OVERVIEW
--------------------------------------------------------------------------------
NyaySahayak is an AI-powered legal assistance and courtroom preparation system
tailored for the Indian legal domain.

The system is structured as a two-tier Multi-Agent Architecture built with
LangGraph (from the LangChain ecosystem) and FastAPI.

The core principle of the system:
"THE CASE GRAPH IS THE SINGLE SOURCE OF TRUTH"
Case documents are analyzed by Tier 1 agents to compile a structured Case Graph.
Downstream Tier 2 agents consume this Case Graph to simulate courtroom proceedings,
test legal arguments, and coach advocates before entering court.


2. IS LANGCHAIN GOOD TO USE? (HONEST VERDICT)
--------------------------------------------------------------------------------
VERDICT: YES for LangGraph & Structured Outputs; NO for raw generic LangChain loaders.

WHY IT IS GOOD:
a. LangGraph is the industry standard for stateful, cyclic multi-agent systems.
   Courtroom prep is inherently cyclic:
   (Counsel makes argument -> Opposing Counsel attacks -> Judge interrogates -> Counsel rebuts).
   Writing this with custom loops and memory is brittle. LangGraph provides
   first-class state persistence, cyclic transitions, and checkpoints.
b. Structured Output: LangChain's `.with_structured_output(PydanticModel)` bridges
   raw LLMs directly into our existing Pydantic schemas (FactItem, TimelineEvent,
   EvidenceItem, CitationVerificationReport) with automatic schema validation.
c. Model Agnosticism: Allows seamless switching between Gemini (fast & long context),
   Claude 3.5 Sonnet (complex legal reasoning), GPT-4o, or local Indian legal models.
d. Human-in-the-Loop: LangGraph natively supports breakpoints where a lawyer can
   review, correct, or approve facts before simulation proceeds.

WHAT NOT TO USE FROM LANGCHAIN:
- Do NOT replace the custom PyMuPDF parser with LangChain DocumentLoaders. Legal
  court filings need page-level coordinates and provenance for admissibility,
  which NyaySahayak's custom parser already handles well.


3. MULTI-AGENT SPECIFICATION: WHAT EACH AGENT DOES
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
TIER 1: CASE GRAPH COMPILER AGENTS (Upstream Document Intelligence)
--------------------------------------------------------------------------------

AGENT 1: FACT FINDER AGENT (app.services.agents.fact_finder)
- Role: Extracts structured facts, parties, and contradictions from case filings.
- How it uses LangChain:
  * Receives document chunks with page provenance.
  * Uses ChatModel with `.with_structured_output(FactExtractionResult)`.
  * Identifies parties (Petitioner, Respondent, State, Interveners, Witnesses).
  * Categorizes statements: Background, Procedural, Substantive, Disputed, Contradiction.
  * Flags contradictory assertions between opposing filings (e.g., Petitioner
    affidavit vs Respondent counter-affidavit).
  * Attaches exact document ID and page number to every fact.

AGENT 2: TIMELINE ENGINE AGENT (app.services.agents.timeline_engine)
- Role: Builds a verified chronological timeline of events with page citations.
- How it uses LangChain:
  * Uses LangChain prompt templates specialized in Indian date formats and legal
    order dates (e.g., "impugned order dated 14.05.2021").
  * Distinguishes exact dates vs approximate dates ("circa 2018", "on or about").
  * Flags conflicting dates (where petitioner claims event occurred in 2019 but
    police records claim 2020).
  * Generates a sorted `List[TimelineEvent]`.

AGENT 3: EVIDENCE MAPPER AGENT (app.services.agents.evidence_mapper)
- Role: Maps claims to documentary exhibits and audits evidence strength.
- How it uses LangChain:
  * Analyzes exhibits, annexures, affidavits, and statutory notices.
  * Rates evidence strength: STRONG, MODERATE, WEAK, or MISSING.
  * Identifies "unsupported assertions" (claims made in the petition that lack
    any supporting annexure or affidavit).
  * Generates structured `List[EvidenceItem]`.

AGENT 4: CITATION VERIFIER AGENT (app.services.agents.citation_verifier)
- Role: Implements the 6-Check Verification Protocol on legal precedents.
- Checks:
  1. Existence Check: Verifies authority format against Indian Law Reports (SCC, AIR, SCR).
  2. Identity Check: Validates party names, court bench, and year.
  3. Source Check: Locates official judgment text in the corpus.
  4. Quotation Check: Verifies exact quotation similarity against original text.
  5. Proposition Check: Uses LLM to determine if cited case actually supports the proposition.
  6. Trace Check: Verifies if the precedent was overruled, distinguished, or affirmed.
- How it uses LangChain:
  * Employs LangChain Tool Calling to search corpus databases deterministically.
  * Uses LLM reasoning node specifically for the Proposition Check (Ratio Decidendi analysis).

AGENT 5: CASE GRAPH COMPILER (app.services.agents.graph_compiler)
- Role: Master coordinator that merges outputs from Agents 1-4 into the unified CaseGraph.
- State: Persists versioned CaseGraph records into SQLite/PostgreSQL.


--------------------------------------------------------------------------------
TIER 2: COURTROOM SIMULATION AGENTS (Downstream Adversarial Simulation)
--------------------------------------------------------------------------------

AGENT 6: OPPOSING COUNSEL AGENT (The Red Teamer)
- Role: Represents the adversarial legal position.
- Behavior:
  * Ingests the Master Case Graph.
  * Actively hunts for weak evidence, conflicting dates, and unverified citations.
  * Formulates counter-arguments, preliminary procedural objections (e.g.,
    Limitation Act, Maintainability of Writ under Article 32/226, Alternative Remedies).
  * Challenges the petitioner's factual claims during sparring sessions.

AGENT 7: BENCH JUDGE AGENT (The Inquisitor)
- Role: Simulates a judge (or a multi-judge bench) of the High Court or Supreme Court.
- Behavior:
  * Probes both counsel with pointed judicial questions.
  * Tests the constitutional doctrine (e.g., Basic Structure, Wednesbury Unreasonableness,
    Proportionality Standard).
  * Demands exact page references and authorities from counsel.
  * Rules on procedural objections raised by the Opposing Counsel.

AGENT 8: COURTROOM COACH AGENT (The Strategist)
- Role: Acts as senior advocate / strategic advisor to the user.
- Behavior:
  * Evaluates the advocate's performance during simulation sparring.
  * Generates a "Courtroom Battle Brief":
    - Rebuttal scripts for anticipated opposing counsel attacks.
    - Bench preparation notes for likely judicial questions.
    - Citation cards with verified page and paragraph numbers.


4. LANGGRAPH WORKFLOW STATE MACHINE
--------------------------------------------------------------------------------

State Schema (TypedDict):
-------------------------
class CourtroomState(TypedDict):
    case_id: str
    case_graph: CaseGraph
    user_argument: str
    active_issue: str
    opposing_arguments: List[str]
    judge_questions: List[str]
    coach_feedback: List[str]
    current_speaker: str
    turn_count: int
    session_status: str

Workflow Graph:
---------------
        [ User Inputs Argument ]
                   │
                   ▼
       ┌───────────────────────┐
       │ Opposing Counsel Node │ ◄── Attacks argument using Case Graph
       └───────────┬───────────┘
                   │
                   ▼
       ┌───────────────────────┐
       │   Bench Judge Node    │ ◄── Interrogates counsel with bench questions
       └───────────┬───────────┘
                   │
                   ▼
       ┌───────────────────────┐
       │ Courtroom Coach Node  │ ◄── Provides actionable feedback & rebuttals
       └───────────┬───────────┘
                   │
                   ▼
        [ Next Turn / Summary ]
